# シンプルセキュリティツールキット
このリポジトリは、スマートコントラクト開発のための実用的なセキュリティ重視のガイドとチェックリストのコレクションであり、[Nascent](https://www.nascent.xyz/)チームがポートフォリオ企業や、これが役立つと思われるエコシステム内の他の人々と共有するために集めたものです。これは包括的なものではなく、特にプロトコルの初期バージョンを開発・管理しているチームに適していると思われる、実用的で独自の見解に基づいた推奨事項に偏っています。

### 目次

1. **[開発プロセス](https://github.com/nascentxyz/simple-security-toolkit/blob/main/development-process.md)**

安全なコードベースを持つための最も重要な要素の一つは、堅実な開発プロセスです：「予防は治療に勝る」。このドキュメントでは、Nascentで私たちが上手く機能していると感じている開発プロセスの例を示しています。初期設計と機能要求 -> 仕様 -> 評価 -> 実装 -> テスト -> デプロイメント -> モニタリングまでのステップを説明しています。

2. **[監査準備チェックリスト](https://github.com/nascentxyz/simple-security-toolkit/blob/main/audit-readiness-checklist.md)**

監査は高価で時間がかかり、数ヶ月前に予定を立てる必要があります。このチェックリストを完了することで、コードベースが外部レビューの準備ができていることを確認し、可能な限り多くの簡単な問題を事前に発見することができます。これにより、監査人はより深刻で重要な脆弱性の特定に時間と注意を集中させることができます。

3. **[ローンチ前セキュリティチェックリスト](https://github.com/nascentxyz/simple-security-toolkit/blob/main/pre-launch-security-checklist.md)**

メインネットにコードをデプロイする前に、チームはこのチェックリストを完了して、潜在的なバグやセキュリティインシデントの報告と対応を可能にするために必要な手順を踏んだことを確認する必要があります。

4. **[インシデント対応計画テンプレート](https://github.com/nascentxyz/simple-security-toolkit/blob/main/incident-response-plan-template.md)**

どのプロジェクトもセキュリティインシデントが発生することを予想していません。事前に計画を文書化しておくことで、アドレナリンが高まっている緊迫した状況でも、チームが迅速かつ冷静に対応するのに役立ちます。


### 貢献について

貢献に興味を持っていただきありがとうございます！私たちはこのリポジトリに追加されるものについて*非常に*独自の見解を持っています。しかし、外部の貢献者からの提案を受け入れる姿勢があり、そうすることをお勧めします。新しいドキュメントのアイデアがある場合は、PRを開始する前に問題を提起して私たちの支持を確認するのが最善でしょう。既存のドキュメントに提案がある場合は、すぐにPRを開くことができます。

このリポジトリをフォークして独自のものにすることを自由に行ってください。あなたのチームとアイデアを共有し、改良してください。より広範なチームに役立つかもしれないことを見つけた場合は、PRを開くことを検討してください！
